# Web Dashboard Service

## Общие принципы работы

Сервис `web_dashboard` — это веб-интерфейс для визуализации метрик в реальном времени, получаемых от сервера метрик (`metrics_server`). Дашборд предоставляет интерактивные графики, аналитику и управление отображаемыми метриками.

### Основные функции

- **Real-time визуализация**: Отображение метрик в реальном времени через Server-Sent Events (SSE)
- **Интерактивные графики**: Построение временных рядов с использованием Chart.js
- **Аналитика метрик**: Расчёт и отображение статистики (среднее, мин/макс, тренды)
- **Гибкая настройка**: Регулировка интервала обновления и глубины истории
- **Выбор метрик**: Динамическое включение/отключение отображаемых метрик

## Архитектурные особенности

### Компоненты

#### 1. HTTP Server (`server.py`)
Минимальный HTTP-сервер на базе Python для отдачи статических файлов.

**Функции:**
- Раздача статических файлов из директории `static/`
- Поддержка CORS (Cross-Origin Resource Sharing) для доступа с других доменов
- Отключение кэширования (`Cache-Control: no-cache`) для актуальности данных
- Настройка хоста и порта через аргументы командной строки

**Конфигурация:**
```bash
python -m web_dashboard.server --host 0.0.0.0 --port 4000
```

#### 2. Frontend (`static/`)

##### `index.html`
Точка входа приложения. Содержит:
- Подключение библиотек: Chart.js, Luxon (для работы со временем), Chart.js Adapter для Luxon
- Инициализацию веб-компонента `<metrics-dashboard>` с параметрами:
  - `server-url`: URL сервера метрик
  - `interval`: Интервал обновления (секунды)
  - `minutes`: Глубина истории (минуты)

##### `metrics-dashboard.js`
Веб-компонент `MetricsDashboard`, реализующий всю логику дашборда.

**Архитектура компонента:**

**Хранилища данных:**
- `metricsDataStore`: Map для накопления всех точек каждой метрики (для построения графиков)
- `charts`: Map активных Chart.js графиков
- `selectedMetrics`: Set выбранных пользователем метрик
- `allAvailableMetrics`: Список всех доступных метрик с сервера

**Словарь локализации (`metricConfig`):**
Конфигурация для каждой метрики:
- `title`: Человеко-читаемое название
- `unit`: Единица измерения (%, МГц, Б)
- `min/max`: Границы оси Y
- `step`: Шаг сетки оси Y
- `formatBytes`: Флаг форматирования байтов в КБ/МБ/ГБ

**Основные методы:**

1. **`initDashboard()`**: Инициализация
   - Получение списка метрик с `/metrics/names`
   - Автоматический выбор первых 3 метрик
   - Рендеринг переключателей метрик и графиков
   - Подключение к SSE потоку

2. **`_connectToStreamImpl()`**: Подключение к SSE
   - Формирование URL: `/metrics/stream?interval=X&minutes=Y&metrics=A,B,C`
   - Создание `EventSource` для real-time обновлений
   - Обработка событий: обновление графиков, статуса соединения
   - Автоматическое переподключение с экспоненциальной задержкой (5s → 60s)

3. **`updateCharts(metricsData)`**: Обновление графиков
   - Добавление новых точек в `metricsDataStore` (без дублирования по timestamp)
   - Сортировка точек по времени
   - Удаление старых точек за пределами окна (`cutoff = now - minutes * 60 * 1000`)
   - Обновление Chart.js графиков

4. **`fetchAnalysis()`**: Загрузка аналитики
   - GET запрос на `/metrics/analysis?metrics=A,B,C&minutes=X`
   - Расчёт статистики на сервере
   - Отображение: среднее, мин/макс, последнее значение, тренд

5. **`rebuildCharts()`**: Перестройка графиков
   - Создание/удаление графиков при изменении выбора метрик
   - Сохранение данных в `metricsDataStore` при пересоздании

6. **`applyParameters()`**: Применение параметров
   - Валидация интервала (1-300 сек) и глубины (1-1440 мин)
   - Обновление атрибутов компонента
   - Переподключение к SSE с новыми параметрами
   - Обновление временного окна графиков

**Механизм debounce:**
Для предотвращения частых переподключений при изменении параметров используется debouncing:
- `_debounceTime = 3000ms`
- Изменения накапливаются, подключение происходит через 3 секунды после последнего изменения
- Кнопка "Применить" показывает статус изменений (pending/applied)

**Обработка heartbeat от компрессора:**
Дашборд корректно обрабатывает heartbeat-точки от cpu_monitor:
- При получении точки с неизменным значением (heartbeat) она добавляется в график
- Это позволяет визуально отличать:
  - **Неизменную метрику**: Горизонтальная линия с периодическими точками (heartbeat)
  - **Отсутствие метрики**: График не обновляется, нет новых точек
- Статистика аналитики также обновляется с учётом heartbeat-точек

### Конфигурация компонента

Параметры веб-компонента в HTML:
```html
<metrics-dashboard 
    server-url="http://localhost:8000"
    interval="10" 
    minutes="10">
</metrics-dashboard>
```

| Параметр | Описание | Диапазон | По умолчанию |
|----------|----------|----------|--------------|
| `server-url` | URL сервера метрик | - | `http://localhost:8000` |
| `interval` | Интервал обновления (сек) | 1-300 | `20` |
| `minutes` | Глубина истории (мин) | 1-1440 | `30` |

### Визуальные элементы

1. **Индикатор статуса**: 
   - 🔵 `connecting` — подключение
   - 🟢 `online` — подключено,实时更新
   - 🔴 `error` — ошибка
   - ⚪ `offline` — отключено

2. **Переключатели метрик**: 
   - Чипсы с названиями метрик
   - Активные/неактивные состояния
   - Иконки (+/✓)

3. **Графики**:
   - Адаптивная сетка (CSS Grid)
   - Линейные графики с заполнением
   - Временная ось с Luxon
   - Тултипы с форматированными значениями

4. **Панель аналитики**:
   - Таблица статистики по выбранным метрикам
   - Среднее, мин/макс, последнее значение
   - Тренд (растёт/убывает) с указанием скорости изменения в секунду

5. **Параметры обновления**:
   - Поля ввода интервала и глубины
   - Кнопка "Применить" с индикацией изменений
   - Визуальные уведомления об успешном применении

### Преимущества архитектуры

1. **Real-time обновления**: SSE обеспечивает низкую задержку доставки метрик
2. **Эффективность**: Debouncing предотвращает избыточные подключения
3. **Надёжность**: Автоматическое переподключение с экспоненциальной задержкой
4. **Гибкость**: Динамический выбор метрик и настройка параметров
5. **Информативность**: Heartbeat-точки позволяют видеть стабильные метрики
6. **Аналитика**: Встроенная статистика и тренды для быстрого анализа

### Диаграмма потока данных

```
[Metrics Server] → (SSE Stream) → [EventSource]
                                       ↓
                              [updateCharts()]
                                       ↓
                              [metricsDataStore]
                                       ↓
                              [Chart.js Update]
                                       ↓
                                 [DOM Render]

[User Input] → [applyParameters()] → [flushConnectToStream()]
                                           ↓
                                    [new SSE connection]
                                            ↓
                                     [fetchAnalysis()]
```

### Интеграция с cpu_monitor

Дашборд корректно работает с обновлённой моделью cpu_monitor:
- **Heartbeat-точки**: Отображаются как обычные точки, обеспечивая видимость стабильных метрик
- **Сжатые данные**: Компрессор отправляет только значимые изменения + heartbeat, дашборд накапливает все точки
- **Отличие состояний**:
  - Метрика стабильна: последние точки имеют одинаковое значение (heartbeat)
  - Метрика не отслеживается: нет новых точек в течение `interval * 2+` секунд
