# CPU Monitor Service

## Общие принципы работы

Сервис `cpu_monitor` — это агент сбора метрик процессора, который работает на клиентской машине и отправляет данные на центральный сервер метрик (`metrics_server`). Агент реализует интеллектуальную систему сжатия данных для оптимизации сетевого трафика.

### Основные функции

- **Сбор метрик**: Периодический сбор данных о загрузке CPU (по ядрам и общей), частоте процессора, использовании памяти
- **Потоковое сжатие**: Использование алгоритма Sausage Links для сжатия временных рядов метрик
- **Heartbeat-механизм**: Отправка keepalive-сигналов для неизменных метрик
- **Пакетная отправка**: Группировка сжатых данных перед отправкой на сервер

## Архитектурные особенности

### Компоненты

#### 1. Collector (`collector.py`)
Модуль сбора метрик. Использует системные вызовы для получения данных о:
- Загрузке каждого ядра CPU (%)
- Общей загрузке CPU (%)
- Текущей частоте процессора (MHz)
- Использовании оперативной памяти

Сбор происходит с настраиваемым интервалом (по умолчанию 0.5 секунды).

#### 2. Compressor (`compressor.py`)
Модуль сжатия данных на основе алгоритма **Sausage Links**.

**Ключевые особенности:**
- **Потоковое сжатие**: Каждая метрика имеет собственный `StreamingCompressor`
- **Адаптивное отклонение**: Параметры `deviation`, `auto_dev_factor`, `ema_alpha` настраиваются через переменные окружения
- **Буферизация**: Все сырые точки накапливаются в буфере для пересжатия при добавлении новых данных
- **Отслеживание отправленных точек**: Множество `_sent_timestamps` предотвращает дублирование отправленных данных

**Heartbeat-механизм:**
Для решения проблемы различения "метрика не отслеживается" и "метрика неизменна" реализован механизм heartbeat:
- Параметр `max_silent_interval` (по умолчанию 10 секунд) определяет максимальный интервал молчания
- Если метрика не отправлялась дольше этого интервала, последняя известная точка отправляется принудительно как keepalive-сигнал
- Heartbeat-точки не добавляются в `_sent_timestamps`, так как это повторяющиеся значения
- В логах компрессора heartbeat отмечается сообщением: `[COMPRESSOR] Heartbeat sent: (timestamp, value)`

**Алгоритм работы компрессора:**
1. Новые точки добавляются в общий буфер `_all_points`
2. Все точки пересжимаются через Sausage Links
3. Фильтруются только те точки, которые ещё не были отправлены (кроме последней — "открытый сегмент")
4. Проверяется heartbeat: если прошло больше `max_silent_interval` с последней отправки, отправляется последняя известная точка с текущим timestamp
5. Возвращаются точки для отправки

#### 3. Sender (`sender.py`)
Модуль отправки данных на сервер.

**Функции:**
- Формирование JSON payload в формате: `[{metric, value, timestamp}, ...]`
- Отправка POST-запросов на эндпоинт `/metrics/put_batch`
- Обработка ошибок сети

#### 4. Main (`main.py`)
Основной модуль управления агентом.

**Архитектура:**
- **MetricStream**: Класс-обёртка для каждой метрики, управляющий собственным компрессором и буфером сжатых точек
- **Два потока выполнения**:
  - `collect_loop`: Цикл сбора данных с заданным интервалом
  - `send_loop`: Цикл отправки пакетов с заданным интервалом
- **Graceful shutdown**: При остановке агента выполняется финальная отправка всех оставшихся точек через `final_flush()`

### Конфигурация через переменные окружения

| Переменная | Описание | По умолчанию |
|------------|----------|--------------|
| `METRICS_API_URL` | URL сервера метрик | `http://localhost:8000` |
| `CPU_COLLECTION_INTERVAL` | Интервал сбора метрик (сек) | `0.5` |
| `BATCH_SEND_INTERVAL` | Интервал отправки пакетов (сек) | `3.0` |
| `CPU_COMPRESSOR` | Тип компрессора (`none` или `sausage_links`) | `none` |
| `COMPRESSOR_DEVIATION` | Базовое отклонение для сжатия | `1.0` |
| `COMPRESSOR_AUTO_DEV_FACTOR` | Фактор адаптивного отклонения | `0.5` |
| `COMPRESSOR_EMA_ALPHA` | Коэффициент сглаживания EMA | `0.3` |
| `COMPRESSOR_MAX_SILENT_INTERVAL` | Максимальный интервал молчания для heartbeat (сек) | `10.0` |

### Преимущества архитектуры

1. **Эффективность**: Сжатие временных рядов значительно уменьшает объём передаваемых данных
2. **Надёжность**: Heartbeat-механизм позволяет отличать отсутствие данных от стабильных значений
3. **Масштабируемость**: Каждая метрика обрабатывается независимо
4. **Гибкость**: Все параметры настраиваются через переменные окружения
5. **Отказоустойчивость**: При ошибках отправки агент продолжает сбор данных

### Диаграмма потока данных

```
[Сбор метрик] → [Collector] → [MetricStream per metric]
                                      ↓
                              [StreamingCompressor]
                                      ↓
                            (сжатие + heartbeat check)
                                      ↓
                              [Compressed Buffer]
                                      ↓
                               (batch interval)
                                      ↓
                                 [Sender]
                                      ↓
                              [Metrics Server]
```
